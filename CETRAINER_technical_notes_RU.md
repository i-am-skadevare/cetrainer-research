# CETRAINER Research: Barracuda и MrAntiFun

**Автор исследования:** Pauline Solheim (`skadevare`)  
**GitHub:** [@i-am-skadevare](https://github.com/i-am-skadevare)

**Тип работы:** исследование форматов CETRAINER, анализ существующих Python-скриптов, извлечение данных из архивов автономных трейнеров, диагностика XOR-преобразований и проверка восстановленных XML-таблиц.

> Это отчёт о двух конкретных экземплярах трейнеров: Watch Dogs от Barracuda и Splinter Cell: Blacklist от MrAntiFun. Он не заявляет поддержку всех трейнеров этих авторов и не представляет исходные алгоритмы AlexAltea как мою собственную разработку.

## 1. Цель исследования

Я изучала внутреннее устройство двух защищённых файлов Cheat Engine, чтобы понять, почему стандартные методы восстановления содержимого работают не для всех вариантов формата.

В качестве отправной точки использовался проект [AlexAltea/cetrainer-unpacker](https://github.com/AlexAltea/cetrainer-unpacker), включающий отдельные реализации для Barracuda и MrAntiFun.

Моя задача состояла не в разработке универсального декодера, а в исследовании конкретных файлов: анализе исходного кода, проверке предполагаемых преобразований, диагностике ошибок и получении результата, корректность которого можно проверить по структуре XML, размеру и SHA-256.

Были исследованы два независимых случая:

- **Watch Dogs / Barracuda / Cheat Engine 6.7**
- **Splinter Cell: Blacklist / MrAntiFun / Cheat Engine 6.4, 32-bit**

**Условие обнаружения файлов для обоих кейсов:** соответствующий автономный `.exe`-трейнер должен был быть запущен. Исследуемые файлы и временно распакованные компоненты обнаруживались через каталог `%TEMP%\cetrainers` (эквивалентная запись: `%temp%/cetrainers`) во время работы трейнера. Это важная часть процедуры получения исходных материалов: речь не о файлах, которые обязательно лежали рядом с `.exe` до запуска.

## 2. Исходные проекты и алгоритмы

Основные источники:

- [Исходный скрипт Barracuda](https://github.com/AlexAltea/cetrainer-unpacker/blob/master/unpackers/unpack_cet_barracuda.py)
- [Исходный скрипт MrAntiFun](https://github.com/AlexAltea/cetrainer-unpacker/blob/master/unpackers/unpack_cet_mrantifun.py)
- [Общая документация CETRAINER](https://github.com/AlexAltea/cetrainer-unpacker/blob/master/docs/cetrainer.md)
- [Документация варианта Barracuda](https://github.com/AlexAltea/cetrainer-unpacker/blob/master/docs/cetrainer-barracuda.md)
- [Документация варианта MrAntiFun](https://github.com/AlexAltea/cetrainer-unpacker/blob/master/docs/cetrainer-mrantifun.md)

В общем случае защищённый `.CETRAINER` содержит сжатую XML-таблицу Cheat Engine, обработанную несколькими XOR-преобразованиями. У автономного трейнера `.EXE` может быть дополнительный упаковочный слой: архив содержит собственно `.CETRAINER`, исполняемый файл движка Cheat Engine и необходимые DLL.

Поэтому в обоих исследованиях важно было различать **извлечение файла из контейнера** и **декодирование самого файла**.

### Общая часть преобразований

Обе исходные реализации используют две цепочечные XOR-волны.

Первая волна проходит по данным от начала к концу:

```python
for i in range(2, len(data)):
    data[i] ^= data[i - 2]
```

Вторая волна проходит в обратном направлении:

```python
for i in range(len(data) - 2, -1, -1):
    data[i] ^= data[i + 1]
```

После этого применяются дополнительные XOR-проходы. Именно на этом этапе рассматриваемые варианты начинают отличаться.

Оригинальный скрипт Barracuda проверяет ключи `0xCB` и `0xCF`. Скрипт MrAntiFun проверяет несколько последовательностей начальных ключей, включая `2A AD 2B 41`, обозначенную автором как вариант модифицированного Cheat Engine 6.4, 32-bit.

### Доработки диагностического кода

В процессе исследования я подготовила изменённые Python-версии, в которых основное внимание уделялось наблюдаемости и проверке результата.

Были добавлены или расширены:

- вывод размера и SHA-256 исходного файла;
- просмотр первых байтов в шестнадцатеричном формате;
- диагностика результатов цепочечных XOR-преобразований;
- вывод проверяемого профиля и ошибок декомпрессии;
- попытки распаковки raw DEFLATE, zlib и gzip;
- осторожная обработка четырёхбайтового поля перед XML;
- сохранение хеша, размера и пути итогового файла;
- отделение распакованных, но непроверенных данных от результата, распознанного как XML.

Для большого файла Barracuda также был добавлен предварительный поиск по короткому префиксу: для каждого однобайтового ключа преобразуется только часть файла, а полная проверка выполняется для кандидатов, прошедших предварительный отбор. Отдельно предусматривался более медленный исчерпывающий режим.

Этот поиск не оказался окончательным решением для Watch Dogs, но был полезен для диагностики и исключения известных вариантов.

## 3. Case Study A — Watch Dogs / Barracuda

### 3.1. Исходный файл

Исследовался файл `CET_TRAINER.CETRAINER`.

| Параметр | Значение |
|---|---|
| Размер защищённого файла | 214 896 байт |
| SHA-256 | `8b4c801a0ed057f99e2066092a4a1ea21e6b667a0cfb1600d09a6ce159219618` |
| Версия Cheat Engine | 6.7, подтверждена в восстановленном LuaScript |
| Целевой процесс | `watch_dogs.exe` |

Для получения файлов этого кейса был запущен автономный `.exe`-вариант трейнера; исследуемые файлы обнаруживались через `%TEMP%\cetrainers` во время его работы. `CET_TRAINER.CETRAINER` присутствовал внутри `CET_Archive.dat` автономного трейнера. После извлечения он совпал по размеру и SHA-256 с отдельным экземпляром `CET_TRAINER.CETRAINER`, который использовался в ранних диагностических попытках.

### 3.2. Почему исходный скрипт не подошёл

Исходный `unpack_cet_barracuda.py` выполняет две цепочечные XOR-волны, а затем пробует incrementing-XOR-ключи `0xCB` и `0xCF`.

В нашем случае ни эти профили, ни стандартный профиль Cheat Engine с начальным ключом `0xCE` не дали корректного результата.

В ранних журналах зафиксированы ошибки raw-DEFLATE, в том числе:

- `invalid block type`;
- `invalid distance too far back`;
- `invalid code lengths set`.

Это показывало, что полученные последовательности байтов не соответствуют ожидаемому сжатому потоку.

Мы также расширили диагностические попытки: проверяли несколько вариантов декомпрессии, заголовки и возможные смещения, фиксировали байтовые префиксы и хеши кандидатов.

Первоначальный режим поиска ключа имел ограничение для файлов крупнее 131 072 байт. Позднее поиск был переработан: вместо обработки всего файла на каждом этапе предварительно проверяется префикс размером до 16 KiB. Это уменьшило ненужную работу, но не обнаружило нужный вариант автоматически.

### 3.3. Обнаруженный вариант

Решение появилось после добавления специальной ветки для конкретного формата.

Для исследованного файла подтверждена следующая последовательность.

**Первый этап — две цепочечные XOR-волны.**

Применяются два прохода, описанных выше.

**Второй этап — XOR с шагом 5.**

Начальное значение ключа — `0xCA`. После обработки каждого байта ключ изменяется так:

```python
key = (key + 5) & 0xFF
```

Этот проход отличается от исходных профилей Barracuda, где ключ увеличивается на единицу.

**Третий этап — распознавание контейнера.**

После преобразования начало буфера имеет сигнатуру:

```text
BRICKED 00 15 00
```

В шестнадцатеричном представлении это `42 52 49 43 4B 45 44 00 15 00`, то есть десятибайтовый заголовок `BRICKED\x00\x15\x00`.

**Четвёртый этап — raw DEFLATE.**

Сжатый поток начинается со смещения 10, сразу после этой сигнатуры. Попытки распаковать данные без учёта заголовка не давали корректного результата.

**Пятый этап — поле длины и XML.**

После распаковки получается 357 452 байта. Первые четыре байта представляют little-endian-поле длины XML. Оно содержит значение `357448`; следующие 357 448 байт составляют XML-таблицу.

Перед принятием результата скрипт проверяет совпадение объявленной длины с фактической и разбирает XML, ожидая корневой элемент `CheatTable`.

### 3.4. Подтверждение результата

Восстановленный XML имеет следующие характеристики:

| Проверка | Результат |
|---|---|
| Размер XML | 357 448 байт |
| SHA-256 | `3fc8017e7a417ec38e675dcb357839f10b7bfe8f63fff371953a0fd2f7a8bb08` |
| Корневой элемент | `CheatTable` |
| Атрибут версии формата таблицы | `CheatEngineTableVersion="26"` |
| Требуемая версия движка | `RequiredCEVersion=6,7` |
| Целевой процесс | `watch_dogs.exe` |

Поле `CheatEngineTableVersion="26"` обозначает версию формата таблицы, а не установленный движок Cheat Engine. Требование версии 6.7 подтверждается отдельно — содержимым LuaScript.

### 3.5. Итог по Barracuda

Для исследованного экземпляра Watch Dogs исходные ключи `0xCB` и `0xCF` оказались недостаточны. Мы обнаружили и реализовали отдельную ветку, использующую начальный ключ `0xCA`, шаг `+5`, сигнатуру `BRICKED` и raw-DEFLATE-поток со смещения 10.

Корректность результата подтверждена совпадением длины, успешным разбором XML и наличием ожидаемых сведений о целевом процессе и версии движка.

Я не утверждаю, что этот вариант используется всеми трейнерами Barracuda. Вывод относится к конкретному файлу.

## 4. Case Study B — Splinter Cell: Blacklist / MrAntiFun

### 4.1. Исходные материалы и версия движка

Для этого кейса также требовался запущенный автономный `.exe`-вариант трейнера. Во время его работы исследуемый набор файлов обнаруживался через временный каталог `%TEMP%\cetrainers`; запуск `.exe` был обязательным условием доступа к этим runtime-файлам.

На начальном этапе исходным контейнером для анализа был архив `CET_Archive.dat` размером 4 426 978 байт, обнаруженный в рамках этой процедуры. В ходе анализа из него извлекались или идентифицировались следующие компоненты:

- `defines.lua`;
- `lua5.1-32.dll`;
- `dbghelp.dll`;
- вложенный исполняемый файл Cheat Engine размером 7 702 528 байт;
- внешний исполняемый файл трейнера размером 200 888 байт.

Важно для хронологии: `decrypt_cetrainer_mrantifun.py` **не был исходным файлом из начального набора материалов**. Сначала мы обратились к оригинальному `unpack_cet_mrantifun.py` из проекта AlexAltea, изучили его реализацию и заметили проблемы, которые затем исправили в собственной диагностической версии. Это описано в разделах 4.3–4.4.

**Уточнение об имени декодированного файла:** `CET_TRAINER.CETRAINER.decoded.CT` размером 868 923 байта не является отдельной записью исходного архива или независимым контрольным файлом. Он содержит тот же декодированный XML, который сохраняется под именем `CET_TRAINER.CETRAINER.decoded.xml`; `.CT` — лишь альтернативное имя/расширение того же содержимого. Поэтому файл `.CT` нельзя считать независимым эталоном или отдельным подтверждением корректности декодирования.

Во вложенном движке обнаружена строка `Cheat Engine 6.4`. PE-заголовок подтверждает архитектуру Intel i386 (PE32), а `lua5.1-32.dll` согласуется с 32-битной сборкой.

Таким образом, исследуемый вариант связан с Cheat Engine 6.4, 32-bit.

### 4.2. Извлечение защищённого CETRAINER

Отдельного исходного защищённого `.CETRAINER` на верхнем уровне архива не было, однако сам файл находился внутри `CET_Archive.dat`.

Для исследованного контейнера после четырёхбайтового префикса применялась распаковка raw DEFLATE. В распакованном архивном потоке присутствует каталог из 21 записи. Первая запись называется `CET_TRAINER.CETRAINER`, а её размер указан как 690 417 байт.

Извлечённый файл имеет:

| Параметр | Значение |
|---|---|
| Размер | 690 417 байт |
| SHA-256 | `7328d2bde49d6d1c10269483c6bcbbf5ed6ec91002afd9ada26b9a11a2f28749` |
| Начальные байты | `0d 0b 13 1c 68 ac be 11 7f e2 0d 40 ...` |

Это позволило перейти от внешнего исполняемого трейнера к содержимому, которое непосредственно обрабатывает декодер.

### 4.3. Изучение исходного скрипта AlexAltea

Оригинальный `unpack_cet_mrantifun.py` содержит три последовательности начальных ключей:

| Профиль | Начальные ключи |
|---|---|
| Modified CE 6.4, 32-bit | `2A AD 2B 41` |
| Modified CE 6.5, 64-bit | `65 42 17 43 65` |
| Modified CE 6.5, вариант | `65 42 17 43` |

Каждое значение задаёт отдельный XOR-проход по всему буферу. Во время каждого прохода ключ увеличивается на единицу после обработки каждого байта. Все проходы идут после двух цепочечных XOR-волн.

Если результат начинается с `CHEAT`, скрипт пропускает пять байтов заголовка и распаковывает оставшиеся данные посредством raw DEFLATE. После распаковки первые четыре байта удаляются как поле длины.

**Последовательность `2A AD 2B 41` уже присутствовала в исходном проекте.** Мы не открывали этот профиль заново: он был описан у AlexAltea и подходил для дальнейшей проверки извлечённого файла.

При разборе оригинального кода были замечены проблемы:

- Проверка незашифрованного XML записана как `if str(data[:5]) == "<?xml":`. Для `bytes`/`bytearray` в Python 3 это сравнение строкового представления объекта с текстовым маркером, поэтому проверка не работает как задумано. Сравнивать нужно сами байты, например с `b"<?xml"`.
- Блок `except Exception as e: pass` скрывает ошибки всех попыток распаковки. Из-за этого не видно, какой профиль и какой этап обработки не сработал.
- В ветке с маркером `CHEAT` первые четыре байта результата распаковки удаляются без дополнительной проверки, что это поле длины и что после его удаления действительно получается XML.

Поэтому после изучения исходного `unpack_cet_mrantifun.py` мы создали собственный файл `decrypt_cetrainer_mrantifun.py` и внесли в него исправления и диагностические проверки. Этот файл является результатом следующего этапа работы, а не исходным материалом кейса.

### 4.4. Исправления в нашей версии

Наш `decrypt_cetrainer_mrantifun.py` сохраняет исходные профили ключей и порядок ключевых проходов, но исправляет перечисленные места и делает результат проверяемее.

В него добавлены:

- проверка XML по реальным байтам вместо сравнения `str(data[:5])` со строкой;
- вывод размера, SHA-256 и начального префикса исходного файла;
- вывод результата двух цепочечных XOR-волн и префикса после каждого проверяемого профиля;
- сохранение причин ошибок распаковки в диагностическом выводе вместо их молчаливого подавления;
- проверка raw DEFLATE, zlib и gzip;
- вывод длины и SHA-256 распакованного кандидата;
- удаление четырёхбайтового поля только если после удаления результат выглядит как XML;
- сохранение исходного буфера без изменения исходного файла;
- выбор расширения выходного файла по наблюдаемому результату и вывод итоговых сведений.

Ограничение этой диагностической версии: функция `looks_like_xml()` проверяет начальные байты и не выполняет полную структурную проверку XML. Поэтому итоговый XML был отдельно разобран парсером.

### 4.5. Запуск исправленной версии и подтверждение

После извлечения защищённого `.CETRAINER` и исправления найденных проблем я запустила собственный `decrypt_cetrainer_mrantifun.py` на этом файле.

Первым проверялся профиль `2A:AD:2B:41`. Он оказался подходящим.

Наблюдаемая последовательность:

1. После двух цепочечных XOR-волн начало буфера изменилось на `AE A3 A8 B6 A1 D7 6C A4 ...`.
2. После четырёх incrementing-XOR-проходов появился заголовок `CHEAT`.
3. Raw-DEFLATE-поток после пятибайтового заголовка успешно распаковался в 868 927 байт.
4. Первые четыре байта распакованного результата — `3B 42 0D 00`. Это little-endian-значение `868923`.
5. После удаления четырёх байтов получен XML размером 868 923 байта.

Файл `CET_TRAINER.CETRAINER.decoded.CT`, встречавшийся в рабочих материалах, не является отдельным файлом из архива и не представляет независимую контрольную копию. Это то же содержимое декодированной таблицы, которое скрипт выдаёт как `CET_TRAINER.CETRAINER.decoded.xml`, только с расширением `.CT`. Поэтому сравнение этих двух имён не является независимой проверкой результата.

| Проверка | Результат |
|---|---|
| Размер исходного защищённого CETRAINER | 690 417 байт |
| Размер распакованного потока с полем длины | 868 927 байт |
| Размер итогового XML | 868 923 байта |
| SHA-256 итогового XML | `1199d1f301d20b7abe42640b6cbc7b31a0141d048878fa9eeac655dd3634a136` |
| Корневой элемент | `CheatTable` |
| `CheatEngineTableVersion` | `18` |
| Количество форм | 3 (`UDF1`, `UDF2`, `UDF3`) |
| Количество `CheatEntry` | 7 |

SHA-256 итогового XML приведён как контрольная сумма полученного результата. Поскольку файл с именем `CET_TRAINER.CETRAINER.decoded.CT` — это тот же декодированный XML под другим расширением, его хеш не является независимым подтверждением правильности декодирования. Проверка результата в этом кейсе опирается на успешную распаковку raw DEFLATE, соответствие поля длины фактическому размеру, успешный разбор XML и ожидаемую структуру таблицы.

Также было обнаружено расхождение в именах: внешний файл трейнера обозначен как `+6`, тогда как внутреннее название таблицы содержит `+7`. Причина этого расхождения не установлена.

### 4.6. Итог по MrAntiFun

В этом случае мы не открыли неизвестную последовательность ключей: профиль `2A AD 2B 41` уже был описан в оригинальном скрипте AlexAltea. Наш вклад заключался в улучшении диагностики, более осторожной обработке буфера и проверке разных режимов распаковки. Результат проверялся по полю длины, успешному разбору XML и ожидаемой структуре таблицы; SHA-256 фиксирует полученный файл, но не сравнивается здесь с независимым эталоном.

В отличие от Barracuda, здесь удалось извлечь исходный защищённый файл из архивного контейнера и выполнить декодирование до валидной XML-таблицы. Файл `CET_TRAINER.CETRAINER.decoded.CT` не является отдельным архивным элементом или независимым эталоном: это то же декодированное содержимое, которое сохраняется с расширением `.xml`.

## 5. Сравнение двух исследований

| Характеристика | Watch Dogs / Barracuda | Splinter Cell: Blacklist / MrAntiFun |
|---|---|---|
| Версия движка | Требование 6.7 в LuaScript | Встроенный Cheat Engine 6.4, PE32 |
| Защищённый CETRAINER | 214 896 байт | 690 417 байт |
| Исходный профиль | `0xCB` и `0xCF` не сработали | `2A AD 2B 41` сработал |
| Цепочечные XOR-волны | Две | Две |
| Дополнительное XOR-преобразование | Один проход, ключ `0xCA`, шаг `+5` | Четыре прохода: `2A`, `AD`, `2B`, `41`; шаг `+1` внутри каждого |
| Контейнер | `BRICKED\x00\x15\x00` | `CHEAT` |
| Начало raw DEFLATE | Смещение 10 | После пятибайтового заголовка |
| Поле длины после распаковки | Первые четыре байта | Первые четыре байта |
| Размер XML | 357 448 байт | 868 923 байта |
| SHA-256 XML | `3fc8017e7a417ec38e675dcb357839f10b7bfe8f63fff371953a0fd2f7a8bb08` | `1199d1f301d20b7abe42640b6cbc7b31a0141d048878fa9eeac655dd3634a136` |
| Главное наблюдение | Отдельный вариант, отсутствовавший среди проверяемых профилей | Успешное применение известного профиля и структурная проверка XML |

Оба случая показывают, что одинаковое расширение `.CETRAINER` не гарантирует одинаковую схему защиты. Первые две XOR-волны совпадают по структуре, но дополнительные проходы, ключи и заголовки различаются.

## 6. Мой вклад и роль ИИ

Я не заявляю авторство исходных алгоритмов AlexAltea. Моя работа включала:

1. Сбор и изучение исходных файлов и логов.
2. Анализ существующих скриптов и их профилей ключей.
3. Проверку стандартных вариантов на реальных файлах.
4. Улучшение диагностического вывода и проверки результатов.
5. Исследование причины отказа стандартных ключей Barracuda.
6. Реализацию отдельной ветки для `BRICKED`, ключа `0xCA` и шага `+5`.
7. Извлечение защищённого CETRAINER из `CET_Archive.dat` для кейса MrAntiFun.
8. Повторный запуск декодирования и проверку результата по размеру, хешу и структуре XML.
9. Документирование подтверждённых фактов и ограничений.

ИИ я использовала как вспомогательный инструмент для анализа кода, диагностики ошибок и проверки гипотез. Работа велась итеративно: я предоставляла файлы и результаты запусков, уточняла задачу, оценивала выводы и направляла исследование к воспроизводимому результату.

## 7. Ограничения

- Выводы относятся к двум конкретным экземплярам, а не ко всем трейнерам Barracuda, MrAntiFun или Cheat Engine.
- Профили `0xCB`, `0xCF`, `2A AD 2B 41`, `65 42 17 43 65` и `65 42 17 43` взяты из исходного проекта и должны быть атрибутированы AlexAltea.
- Параметры `0xCA`, шаг `+5` и заголовок `BRICKED` подтверждены для исследованного файла Watch Dogs; их распространённость в других трейнерах не установлена.
- Успешная распаковка сама по себе недостаточна. Требуются дополнительные проверки длины и структуры XML.
- Перед публикацией необходимо сохранить ссылки на оригинальные реализации и проверить их лицензии. Чужие исполняемые файлы и полные извлечённые таблицы не следует распространять без проверки прав.
